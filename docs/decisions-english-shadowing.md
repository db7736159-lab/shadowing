# 英语口语跟读 PWA · 选型与决策记录

2026-11-13

## 需求（来自本次对话里已经定下的）

- 用的人：只有本人，不做账号、不做付费、不上架
- 形态：手机浏览器打开的网页（PWA），能装到桌面
- 练法：情景跟读 + 发音打分；要能整段「影子跟读」
- 内容：旅行 + 生活办事两类情景；用户嫌自己出题无聊，希望用网上有趣的对话视频，把文本提炼出来，点词能看意思
- 设备：安卓 + Chrome / Edge
- 评分：先免费方案，同时预留 Azure 精评开关
- 地区：中国大陆
- 数据：不登录、不同步，全部留在本机

## 方案

### 方案 A：纯前端 PWA（已选）

- 技术栈：原生 HTML/CSS/ES Module，无构建、无框架；语音识别用 Web Speech API（`webkitSpeechRecognition`）；示范音频在构建期用 TTS 烘成 MP3；词典是本地 JSON；托管用静态文件 + SSH 反向隧道给手机访问
- 为什么适合：零后端、零密钥、零月费；录音不出手机；改一行代码刷新就生效；手机上「添加到主屏幕」后像 App
- 开发难度 / 维护成本：低。没有服务要打补丁，没有依赖要升级；加内容只要往 `packs/` 丢文件夹
- 目标地区能否顺利使用：能。页面和音频都是静态文件，走的是普通 HTTPS；语音识别调用浏览器内置能力，Edge/Chrome 可用（本机无头 Edge 实测 `webkitSpeechRecognition` 与麦克风接口都在）
- 你得自己管的东西：无密钥。唯一要管的是「电脑开着 + 隧道进程活着」才能访问；想彻底不依赖电脑就传到静态托管
- 主要风险：识别精度受浏览器限制（词级，不是音素级）；国产浏览器（夸克/UC/微信内置）普遍没有语音识别接口，换浏览器才行

### 方案 B：前端 + 自建后端

- 技术栈：Node 或 Python 服务，接云 ASR（讯飞/腾讯云口语评测/Azure），密钥放服务端，前端只发音频
- 为什么适合：能拿到真正的音素级评分；密钥不下发到浏览器，安全
- 开发难度 / 维护成本：中高。要一台一直开着的机器或云服务器、要处理上传、限流、CORS、HTTPS 证书，还要给云服务充值
- 目标地区能否顺利使用：国内云服务没问题，但要实名和开通
- 你得自己管的东西：服务器、域名证书、云厂商密钥、账单
- 主要风险：为了一个人练习维护一套后端，长期看是负担

### 方案 C：现成 App / 微信小程序

- 技术栈：买或用现成产品；小程序要主体资质 + 审核
- 为什么适合：最快能用上，内容往往更全
- 开发难度 / 维护成本：几乎为零，但不可定制
- 目标地区能否顺利使用：能
- 你得自己管的东西：无（但改不了任何东西，比如想加自己拍的对话、想调打分权重）
- 主要风险：练法被产品定死；「点词查义 + 影子跟读 + 自己的场景」这种组合基本找不到现成的

## 推荐与结论

**选方案 A。** 起决定作用的一条：一个人自用、内容还要自己长出来的工具，最贵的是维护成本；方案 A 没有任何需要持续照顾的服务，内容用 JSON + 一个 Python 脚本就能扩，评分想升级时再接 Azure（已在设置里留好开关）。

内容侧同时做了个折中：先由我写 6 个情景包（旅行 3 + 生活 3，共 60 句，含中文和发音提示），示范音频在构建期用 TTS 烘成 MP3，这样不依赖手机自带 TTS、也没有运行时网络请求。真人视频包留到下一步：播放器已经支持 `format: "timeline"` + `video`（按句时间轴播放、循环单句），把视频和字幕做成 pack 就能直接练。

## 仍然待定 / 下一步

- 真人**对话**内容来源：YouTube 的视频下载在这台机器上被卡住（`yt-dlp` 下载超时），TED 是演讲不是对话。要对话类真人素材，需要另一个稳定来源，或者用户自己给视频/字幕文件
- 「导入自己的视频 + 字幕」功能还没做（IndexedDB 存媒体、SRT/VTT 解析、自动断句）
- Azure 精评的代码路径已通（录音 → 16k WAV → REST），但没有 key，未在真机上验证过

## 第二轮补充（2026-11-13 晚）

**真人视频包做通了**，用的是 TED：从演讲页的 `__NEXT_DATA__` 里拿到 mp4 地址和 HLS 清单，再从 HLS 的 `EXT-X-MEDIA` 里找到 `en` 和 `zh-cn` 字幕轨道，拉 VTT 分片、按标点合并成句、按时间把中文对到句子上，产出 `format: "timeline"` 的包（`packs/talk-30days`，3 分钟、854×480、27MB）。已验证：Edge 里能解码、`duration=190.34`、能 seek 到第 60 秒。

**顺带修了一个必须修的问题**：Python 的 `http.server` 不支持 `Range`，视频跳句会失效（状态码 200 而不是 206）。换成自写的 `tools/serve.mjs`（Node，支持 206），实测 `Range: bytes=0-1023` 返回 206。

**还没解决的**：TED 是单人演讲，不是「对话视频」。对话类真人素材需要 YouTube/B 站这类来源，而这台机器上 `yt-dlp` 下载不下来（两次都超时）。下一步要么换下载通道，要么改成「用户给视频 + 字幕，应用负责切句和播放」的导入模式。

## 第三轮补充（2026-11-13 深夜）

**「导入自己的视频 + 字幕」做完了**，这是绕开下载卡点的路子：用户自己给素材，应用负责切句、对齐、播放、打分。

- 解析器 `app/subtitle.js`：SRT / VTT → cue → 按标点/停顿合并成句；重复滚动字幕去重；中文字幕按时间中点贴到英文句子上。纯函数，7 个单测。
- 存储 `app/importer.js`：视频存 IndexedDB（存 Blob，不复制成 ArrayBuffer），句子和元信息存 localStorage；`mediaUrl()` 在播放时生成 object URL。用 `fake-indexeddb` 在 Node 里跑了存取/删除/互不覆盖的测试。
- 界面：首页入口 + `#/import` 页面 + 包页面「删除这个导入」。

**测试抓到两个真 bug**（都是我自己写的）：

1. 导入 id 用 `Date.now()`，同一毫秒内两次导入会撞 id。改成时间戳 + 随机后缀。
2. IndexedDB 事务的 resolve 写成 `out.result !== undefined ? out.result : out`，查不到 key 时会把整个 IDBRequest 对象当结果返回，删除后 `get()` 拿到的不是 `undefined`。改成 `'result' in out`。

这两个都是「跑一遍才知道」的，写测试是值得的。

**隧道会自己换域名**：localhost.run 的免费隧道跑了半小时左右，域名从 `db58ebb45a3c8a` 换成了 `15786c98afc9ab`，旧地址直接 502。原因是免费层不允许固定子域。这对「每天练」是硬伤——所以正式用之前应该搬到静态托管（Cloudflare Pages / Netlify），隧道只当临时预览。

## 第四轮（2026-11-14）：按确认过的方案补功能

用户确认的路线：**P0 补功能 → P1 GitHub Pages → P2 APK（TWA 套壳）**；识别引擎做成可插拔，豆包留作兜底后接。

P0 实际做的：

- `app/collect.js`：生词本 + 句子收藏，复习计数、按「练得少」排序的复习队列
- 我的词句页（`#/mine`）：生词/句子两个列表，点一条跳回原句，带删除
- 点词弹层加「☆ 收藏」，句子行加「☆ 收藏这句」
- `app/backup.js`：导出/导入全量备份（进度、收藏、设置、天数），**备份里剥掉 Azure key**
- 识别引擎选择：浏览器 / 只录音；豆包选项先占位禁用
- 安卓分享菜单：manifest `share_target` + Service Worker 处理 `POST /share-target`，把文件塞进 IndexedDB，导入页启动时取走

自测：新增 `test/collect.test.mjs` 6 条；合计 25 条断言全过；无头 Edge 截了「我的词句」「练习页收藏态」「设置页」三张图，并用同一浏览器配置验证了「收藏后按钮变 ★ 已收藏」。

**没做的**：APK、托管、豆包接入（等 P1/P2 和用户实测）。

## 第五轮（2026-11-14）：本地 Whisper 自动生成字幕

用户选定「Pages 站 + C（手机本地识别）+ 浏览器识别」。实测与实现：

- 用 `transformers.js` + `whisper-tiny.en`（量化，43MB）在浏览器 WASM 单线程跑
- 本机实测：60 秒音频识别 13.7 秒（约 4.4 倍实时），TED 语音识别质量不错，只有个别词错
- 中文：本地识别不产出中文，按用户确认先不显示（内置包和 TED 包仍有中文）
- 模型随站点发布（`models/`），不走 HuggingFace：**浏览器直连 hf-mirror 被 CORS 挡掉**（实测 `Failed to fetch`），HuggingFace 直连也不通
- base.en（79MB）上传到 GitHub 反复失败（53MB 的 blob 走 API 报 401/超时），所以设置里暂时禁用，只发布 tiny
- 推送方式最后改用 `git -c http.sslBackend=openssl push`：系统 schannel 的证书库用不了，OpenSSL 后端可以

**踩到的坑**：`git push` 大文件会 408/连接重置；GitHub API 并发上传会 connect timeout；最后靠 API 顺序单文件上传成功（30MB 的 blob 可以，53MB 的不行）。
